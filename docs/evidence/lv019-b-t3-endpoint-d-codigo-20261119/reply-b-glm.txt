Escenario: fallo transitorio envuelto (p. ej. `unavailable`) → responde 409 con `existing` o `existing:null`, ocultando el error real y rompiendo la semántica de reintentos. 3. **`key!` sin validar formato.** Si el parser de ruta puede entregar clave vacía o con `/` (p. ej. `%2F` decodificado), `doc(key!)` lanza error de argumento → 500 genérico en vez de `notFound()`, rompiendo la indistinguibilidad 404 de alerta inexistente. Bloquea salvo que el routing ya valide el formato.
4. **413/415 sin esperar drain.** `req.resume()` seguido de respuesta inmediata: con cuerpo aún en vuelo, Node puede cerrar el socket y el cliente recibe `ECONNRESET` en lugar del error. No bloquea seguridad; degrada el manejo de errores.
