# LV-019.B · Incertidumbre del puente de voz C2

**Candidata local sobre `542a758`; no está habilitada para clientes.** DeepSeek señaló que, si se pierde la respuesta de admisión, un reintento exacto del mismo receptor podía devolver `rejected` aunque el primer intento permaneciera incierto. Una unidad reprodujo ese caso (**40/41**). Otros tres controles reprodujeron la misma clasificación después de recibir un acuse sin entregar bytes: fallo de relectura, puerta del entorno restaurada y flag de memoria restaurado.

El ajuste conserva la huella de la solicitud exacta con el principal en el diario local. Si una lectura posterior no permite una nueva admisión, el mismo principal y solicitud permanecen en `unknown` mientras no haya bytes entregados. Un `NODE_ENV` distinto de prueba o el interruptor `LV_VOICE_C2_MEMORY_TEST` apagado hacen que el puente devuelva `disabled` antes de llamar a sus puertos. Si se apaga `LV_VOICE_C1_FIXTURE` o `LV_VOICE_C2_FIXTURE`, el puerto del adaptador devuelve nulo antes de consultar Firestore. Un replay exacto ya incierto puede conservar `unknown` desde su diario en memoria. Un principal o cuerpo distinto se rechaza. El replay conserva cero nuevas admisiones y cero entregas, y la prueba posterior a `sent` mantiene su comportamiento anterior. La recuperación tras reinicio queda fuera del diario volátil.
