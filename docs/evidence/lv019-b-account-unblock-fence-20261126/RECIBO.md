El contrato vigente, la nube y el prototipo firmado quedaron fuera del cambio.

- El [AccountStore](../../../server/account/backend.ts#L334) prueba el mismo ancla y recibo en la transacción de consulta, despacho y conciliación. El cerco y el permiso del sucesor se registran juntos. El primer intento ya confirmado devuelve su recibo y no habilita el sucesor. El primer cerco ya confirmado recupera el mismo permiso y rechaza un POST tardío del predecesor. Una autorización nueva usa un ID propio. Dos autorizaciones alternativas no pueden sustituir el primer sucesor elegido. Una segunda deriva de generación queda en revisión en este primer corte.
- Las [pruebas](../../../server/account/unblockFence.test.ts) ejercen el AccountStore con un doble serial de Firestore. La barrera es la cola transaccional del doble, con orden explícito de invocación. Los ACK sintéticos se pierden después de publicar las escrituras, y cada lectura usa una nueva instancia de AccountStore sobre el mismo almacenamiento. El arnés cubre dos cuentas con el mismo identificador de incidente, recuperación tras ambos ACK, cero POST con ancla inscrita, 409 por época, rival abierto, repetición, guardia recreada, identidad restaurada, autoridad ausente, legado y ejecución fuera de test. Saldos, reservas y libro se conservan en las pruebas de efecto.
- Una prueba de límite hace que un escritor privilegiado simulado borre y recree el recibo idéntico con marcas físicas nuevas. La lectura todavía acepta la historia recreada dentro del supuesto de escritor confiable. La prueba no muestra una vía de cliente ni un efecto adicional sobre el saldo. La operación tampoco acredita una restauración, la procedencia de la autoridad, el corte de escritores anteriores ni la serialización real de Firestore. El ensayo de cero POST siembra el ancla y no demuestra inscripción desde Video.
- **120/120 pruebas en siete suites, sin omisiones**, Node `24.22.3`. `node node_modules/vitest/vitest.mjs run server/account/unblockFence.test.ts server/account/http.test.ts server/account/accountReadIdentity.test.ts server/account/videoBalanceIdentity.test.ts server/account/videoReservationIdentity.test.ts server/commercial/unblockContinuityIndependent.test.mjs server/commercial/alertContractReview.test.mjs --maxWorkers=1 --reporter=verbose`.
