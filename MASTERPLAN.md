## 1. Meta del producto

Desde Vistavo.app, el cliente inicia sesión, sube un video privado, elige idioma de origen y destino entre los pares habilitados, obtiene texto/subtítulos, los revisa y descarga TXT/SRT. Puede añadir voz estándar generada **desde la traducción revisada**. El render final de MP4 es una ampliación posterior y conserva sus propios criterios de calidad.

- Texto y subtítulos: **US$0.10 por minuto de video**.
- Voz opcional: **US$0.10/min adicional**. Texto + voz: **US$0.20/min**. No hay voz sola.
- El precio y el saldo se calculan con la duración del video fuente; el saldo se redondea hacia arriba al segundo. Cada servicio elegido reserva un segundo de saldo por segundo fuente. Ejemplo: 2:10 son US$0.2167 de texto más US$0.2167 de voz (US$0.4333 sin redondear), y reserva 130 o 260 segundos. Para el precio estimado mostrado, se redondea cada servicio al centavo más cercano (mitades hacia arriba) y luego se suman: US$0.22 texto, US$0.22 voz y US$0.44 ambos. Ese redondeo es solo presentación; el consumo de saldo sigue siendo segundos exactos redondeados hacia arriba.
- Solo se muestran/habilitan los pares y capacidades respaldados por LV-004. La meta de diez idiomas/90 direcciones no significa que todas estén listas hoy.
- No procesar si el saldo real no alcanza. No inventar créditos, recargar ni cobrar con compras/PayPal en esta fase.
- Ante una reserva inconsistente, Rob decidió alertar y mantener el servicio para los demás clientes. El trabajo ya admitido puede terminar y sus pasos autorizados se liquidan cuando las comprobaciones financieras lo permiten; una devolución puede quedar pendiente mientras exista un bloqueo adicional. Identificado el dueño, deben detenerse sus videos nuevos hasta resolver el caso, sin impedir la reparación ni devolver saldo más de una vez. Si el dueño es indeterminado, no se atribuye el bloqueo a ninguna cuenta. La guardia de admisión para una devolución vencida está en diseño y aún no se implementa. [Política](docs/specs/LV-019-B-politica-incertidumbre-cuenta.md) · [Diseño de admisión](docs/specs/LV-019-B-admision-video-devolucion-vencida.md).

## 3. Arquitectura objetivo

```text
Vistavo.app / Firebase Auth
  → Hosting same-origin /api/video/**
  → gateway autenticado (verifica ID token de usuario)
  → Cloud Run Files/Video privado por VPC + identidad de servicio
  → GCS privado + Firestore de video separado
  → trabajos asíncronos y proveedores IA

Gateway/worker → API de cuenta → Firestore vistavo-live
                    reserva antes del despacho; captura al éxito;
                    libera solo ante fallo final confirmado; UNKNOWN se reconcilia
```

La API de cuenta es la autoridad del saldo. Las bases de cuenta y video, sus identidades y permisos siguen separados. El navegador nunca determina el usuario con un UID de formulario. El servicio privado conserva autorización de propietario y el ingreso interno. El gateway no es un proxy abierto ni accede directamente a las bases. No crear Cloud SQL.

El dominio `vistavo.app` está registrado y utiliza DNS de Cloudflare; la web se sirve desde Firebase Hosting. La consulta del 17 nov mostró la dirección directa de Hosting y no evidenció el proxy de Cloudflare activado para la web. Los archivos privados de video se preparan en Google Cloud Storage, no en R2; no se ha conectado el procesamiento público. Cualquier cambio futuro de protección o DNS debe verificarse con el dominio y el certificado antes de aplicarlo.
